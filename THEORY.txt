2D PHYSICS SANDBOX - OOP COURSE PROJECT THEORY
================================================

Project Title:
2D Physics Sandbox using C++, SFML, and CMake


1. INTRODUCTION
---------------

This project is a simple 2D Physics Sandbox created as an Object-Oriented Programming
course project. In this sandbox, the user can spawn circles, rectangles, and
triangles, or trace a custom polygon outline with the mouse. Objects fall due to
gravity and bounce when they hit the ground.

The main purpose of this project is not to create a professional physics engine.
The main purpose is to demonstrate important OOP concepts such as:

- Encapsulation
- Inheritance
- Polymorphism
- Abstraction
- Composition
- Operator overloading

The project uses simple physics formulas that are easy to understand and explain.


2. TECHNOLOGIES USED
--------------------

1. C++
   C++ is used as the main programming language because it supports Object-Oriented
   Programming very well.

2. SFML
   SFML stands for Simple and Fast Multimedia Library. It is used to create the
   window, draw shapes, handle keyboard input, handle mouse input, and display text.

3. CMake
   CMake is used to build the project. It helps generate build files and compile
   the project easily.


3. MAIN IDEA OF THE PROJECT
---------------------------

The program opens a 2D window. The user can press keys to create different shapes:

- Press 1 to create a circle
- Press 2 to create a rectangle
- Press 3 to create a triangle
- Press D to enter custom drawing mode, then hold the left mouse button and trace
  an outline. Release the button to create it; press Escape to cancel.

After spawning, each object falls downward due to gravity. When the object reaches
the ground, it bounces upward. The bounce becomes smaller each time because a bounce
factor is used.

The user can also drag objects with the mouse, delete a selected object, pause the
simulation, and reset everything.

5. CLASS DIAGRAM
----------------

The main inheritance structure is:

PhysicsObject
|
+-- Circle
+-- Rectangle
+-- Triangle
+-- CustomPolygon

PhysicsObject is the base class.
Circle, Rectangle, Triangle, and CustomPolygon are derived classes.


6. ROLE OF EACH CLASS
---------------------

1. Vector2

Vector2 is a small class used to store x and y values.
It represents 2D quantities like:

- Position
- Velocity
- Acceleration

Example:
position = (x, y)
velocity = (x speed, y speed)

The Vector2 class also overloads operators like +, -, and * so vector calculations
become simple.

Example:
velocity += acceleration * deltaTime
position += velocity * deltaTime


2. PhysicsBody

PhysicsBody stores the physics data of an object.

It contains:

- position
- velocity
- acceleration
- mass

These data members are private, so they cannot be directly accessed from outside.
They are accessed through getter and setter methods.

PhysicsBody also has an update function that applies the basic physics equations.


3. PhysicsObject

PhysicsObject is the abstract base class for all physics objects.

It contains common behavior and data for all shapes.

It has:

- A PhysicsBody object
- A selected flag
- A bounce factor
- Common update logic

It also has pure virtual functions like:

- draw()
- containsPoint()
- getBottom()
- fixGroundCollision()

These functions are implemented differently by each derived shape.

Because PhysicsObject has pure virtual functions, we cannot create a direct object
of PhysicsObject. This makes it an abstract class.


4. Circle

Circle inherits from PhysicsObject.

It has:

- radius
- SFML CircleShape

It implements:

- How to draw a circle
- How to check whether the mouse clicked inside the circle
- How to detect its bottom point for ground collision


5. Rectangle

Rectangle inherits from PhysicsObject.

It has:

- size
- SFML RectangleShape

It implements:

- How to draw a rectangle
- How to check whether the mouse clicked inside the rectangle
- How to detect its bottom point for ground collision


6. Triangle

Triangle inherits from PhysicsObject.

In SFML, a triangle is created using CircleShape with 3 points.

It implements:

- How to draw a triangle
- How to check whether the mouse clicked near the triangle
- How to detect its bottom point for ground collision

The triangle collision is intentionally kept simple because this is an OOP project,
not an advanced physics engine.


7. Game

Game is the main controller class.

It handles:

- Creating the SFML window
- Handling keyboard events
- Handling mouse events
- Updating objects
- Drawing grid, ground, shapes, and text
- Spawning objects
- Deleting objects
- Resetting the simulation
- Pausing and resuming

The Game class stores objects in this form:

std::vector<std::unique_ptr<PhysicsObject>> objects;

This means the same vector can store circles, rectangles, and triangles using base
class pointers. This is an example of polymorphism.


8. OOP CONCEPTS USED
--------------------

1. Encapsulation

Encapsulation means wrapping data and functions together inside a class and
protecting the data from direct access.

In this project, PhysicsBody stores position, velocity, acceleration, and mass as
private data members.

They are accessed using methods like:

- getPosition()
- setPosition()
- getVelocity()
- setVelocity()

This protects the internal data and keeps the code organized.


2. Inheritance

Inheritance means creating a new class from an existing class.

In this project:

Circle inherits from PhysicsObject.
Rectangle inherits from PhysicsObject.
Triangle inherits from PhysicsObject.

This avoids repeating common code for every shape.


3. Polymorphism

Polymorphism means one interface can have many forms.

In this project, PhysicsObject has virtual functions like draw() and containsPoint().
Each derived class provides its own version of these functions.

The Game class stores all shapes as PhysicsObject pointers:

std::vector<std::unique_ptr<PhysicsObject>> objects;

When the game calls:

object->draw(window);

the correct draw function is called depending on whether the object is a Circle,
Rectangle, or Triangle.

This is runtime polymorphism.


4. Abstraction

Abstraction means showing only important details and hiding unnecessary complexity.

PhysicsObject is an abstract class. It tells that every physics object must have
functions like draw(), containsPoint(), getBottom(), and fixGroundCollision().

But it does not define exactly how every shape will do these tasks. The derived
classes define the details.


5. Composition

Composition means one class contains an object of another class.

In this project, PhysicsObject contains a PhysicsBody object.

This means every physics object "has a" physics body.

Example:
A Circle is a PhysicsObject.
A Circle has a PhysicsBody.


6. Operator Overloading

Operator overloading means giving special meaning to operators for user-defined
classes.

In this project, Vector2 overloads:

+ for vector addition
- for vector subtraction
* for multiplying a vector by a number

This makes physics calculations easier to read.

Example:

velocity += acceleration * deltaTime;
position += velocity * deltaTime;

Without operator overloading, this code would be longer and harder to understand.


9. BASIC PHYSICS USED
---------------------

The physics used in this project is simple motion physics.

Each object has:

- position
- velocity
- acceleration

The equations used are:

velocity = velocity + acceleration * deltaTime
position = position + velocity * deltaTime

In code, it is written as:

velocity += acceleration * deltaTime;
position += velocity * deltaTime;


10. WHAT IS DELTA TIME?
-----------------------

Delta time is the time passed between two frames.

If we use delta time, the movement becomes smooth and does not depend heavily on
the speed of the computer.

For example, if a computer is fast or slow, delta time helps keep the physics more
consistent.


11. GRAVITY
-----------

Gravity is applied as downward acceleration.

In the project:

acceleration = Vector2(0.0f, gravity);

The x acceleration is 0 because gravity does not move objects left or right.
The y acceleration is positive because in SFML, the y-axis increases downward.

So objects fall down when gravity is applied.


12. GROUND COLLISION
--------------------

Ground collision is kept very simple.

Each shape checks whether its bottom point has reached the ground line.

For example:

- Circle bottom = center y + radius
- Rectangle bottom = center y + height / 2
- Triangle bottom = center y + size

If the bottom of the object is below or equal to the ground level, collision is
detected.

Then the object is moved back to sit exactly on the ground.


13. BOUNCING
------------

When an object hits the ground, its vertical velocity is reversed.

The formula is:

velocity.y = -velocity.y * bounceFactor

The minus sign reverses the direction.
The bounce factor reduces the speed.

Example:
If velocity.y is 500 and bounceFactor is 0.55:

new velocity.y = -500 * 0.55 = -275

This makes the object bounce upward, but with less speed than before.
So after each bounce, the object bounces less and eventually stops.


14. WHY ADVANCED PHYSICS IS NOT USED
------------------------------------

This project does not use:

- Box2D
- SAT collision
- impulse solver
- rotation
- friction system
- constraints

These are advanced topics and would make the project difficult to explain.

Since this is a 2nd-year OOP project, the focus is on OOP concepts and simple
understandable physics.


15. GAME LOOP
-------------

The program uses a standard SFML game loop.

The loop runs while the window is open.

Main steps:

1. Handle events
2. Update physics
3. Render graphics

In simple words:

- First, the program checks keyboard and mouse input.
- Then it updates the position and velocity of all objects.
- Then it draws the background, grid, ground, shapes, and text.

-----------------

Escape - Cancel drawing and leave drawing mode

17. HOW OBJECT SELECTION WORKS
------------------------------

When the user clicks the mouse, the program checks whether the click point lies
inside any object.

Each shape has its own containsPoint() function.

- Circle checks distance from center.
- Rectangle checks if the point is inside its boundaries.
- Triangle uses a simple circular area check to keep it easy.

If the object is selected, its outline becomes white and it can be dragged.


18. HOW DRAGGING WORKS
----------------------

When the user selects an object and moves the mouse, the object's position is
changed to follow the mouse.

While dragging, the object's velocity is set to zero so it does not suddenly fly
away after releasing the mouse.


19. WHY SMART POINTERS ARE USED
-------------------------------

The project uses:

std::unique_ptr<PhysicsObject>

This is used because objects are created dynamically, and smart pointers
automatically manage memory.

It avoids manual delete and reduces memory leak risk.

This is still simple enough to explain:

"unique_ptr owns one object and automatically deletes it when it is removed from
the vector."


20. WHY SFML IS USED
--------------------

SFML makes it easy to:

- Open a window
- Draw shapes
- Display text
- Take keyboard input
- Take mouse input

We are not using SFML as a physics engine. We are only using it for graphics and
input.

24. CUSTOM DRAWN POLYGON FEATURE
--------------------------------

The new feature allows a user to draw a custom filled shape with the mouse. Press
D to switch to drawing mode. Hold the left mouse button, trace the outside boundary,
and release the button. The program validates the outline and creates a polygon
physics object if the outline is usable. Press Escape to discard the current trace
and leave drawing mode.

The preview is shown as a yellow line while drawing. The user can create convex
shapes (no inward corners) and concave shapes (at least one inward corner). The
outline must be simple: its boundary cannot cross itself. Very small outlines and
traces with too many points are rejected with a short status message.


25. WHICH CLASSES CHANGED
-------------------------

  Game already receives input and owns the object collection. It now stores the
  current drawing points, switches into and out of drawing mode, filters mouse
  samples, displays the preview, validates the finished outline, and creates the
  new object. Coordinates are converted from window pixels to world coordinates.

CustomPolygon.h and CustomPolygon.cpp
  This is the new derived physics-object class. It stores a list of local vertices
  and the triangles needed to draw its filled area. It implements the same virtual
  functions as the built-in shapes: draw(), containsPoint(), getBottom(), and
  fixGroundCollision().

CMakeLists.txt
  The new source file is listed in the executable target so it is compiled and
  linked with the rest of the project.

README.md and THEORY.txt
  These files describe the new controls, design, algorithms, limitations, and a
  demonstration/review explanation.


26. FROM MOUSE INPUT TO A PHYSICS OBJECT
----------------------------------------

The process can be understood as a pipeline:

Mouse events -> collected points -> clean/validate boundary -> triangulate fill
             -> create CustomPolygon -> store as PhysicsObject -> update and draw

Game keeps drawingPoints in the order in which the user traces the boundary. The
addDrawingPoint() function ignores points outside the usable canvas and skips a new
point when it is less than five pixels from the last stored point. This prevents
mouse jitter from creating many nearly identical vertices. The point count is
capped at 160 so geometry work remains bounded.

When the mouse is released, finishDrawingShape() asks CustomPolygon to validate the
outline. A failed outline is discarded; it never creates a partly initialized
object. For success, Game creates CustomPolygon and puts it in the existing
vector<unique_ptr<PhysicsObject>>. The normal update loop then applies gravity and
ground response through the base-class interface.


27. RIGID GEOMETRY: LOCAL AND WORLD COORDINATES
-----------------------------------------------

The drawn points initially use world coordinates. When CustomPolygon is created,
it calculates an anchor by averaging the vertex positions. Each vertex is stored
relative to this anchor:

localVertex = drawnWorldVertex - anchor
worldVertex = bodyPosition + localVertex

PhysicsBody stores the anchor position. The local vertices describe the permanent
shape, while the body position can change due to gravity or dragging. Since all
vertices receive the same translation, the outline keeps its shape. This is a
simple example of separating an object's geometry from its transform.


28. OUTLINE VALIDATION AND AREA
-------------------------------

The shoelace formula computes the signed area of a polygon. For a list of vertices,
the program sums x_i*y_(i+1) - x_(i+1)*y_i around the boundary and divides by two.
The absolute result is the area used to reject traces that are too small. The sign
shows whether the points were entered clockwise or counterclockwise.

The outline validator also checks the edge lengths and compares non-adjacent edges
for intersection. Adjacent edges are expected to meet at their shared endpoint and
are therefore skipped. A crossing outline is rejected because its inside region
would be ambiguous for this introductory implementation. Triangulation failure is
also treated as invalid input.


29. TRIANGULATING CONCAVE SHAPES
-------------------------------

An SFML convex shape is not suitable for rendering every concave outline. A concave
shape has an inward notch; filling it as one convex polygon could incorrectly cover
the notch. CustomPolygon instead draws its fill as a group of triangles and draws
the original boundary as a separate line.

The triangles are produced by ear clipping. The algorithm looks at three
consecutive remaining vertices. A candidate ear must turn in the direction of the
polygon's winding and no other remaining point can lie inside its triangle. A valid
ear is added to the fill and its middle vertex is removed. The algorithm repeats
until only three vertices remain; those form the last triangle. The winding check
uses the sign of the polygon area so clockwise and counterclockwise traces both
work.

The triangle vertices are submitted in an SFML VertexArray using the Triangles
primitive. A LineStrip renders the boundary, including a final segment back to the
first point. The geometry is prepared when the object is created and reused while
drawing, rather than being triangulated every frame.


30. POLYGON SELECTION AND GROUND CONTACT
----------------------------------------

The point-in-polygon test uses ray casting. Imagine a ray extending right from the
mouse click. Each time it crosses an edge, the inside flag is toggled. If the flag
is true after checking all edges, the click is inside the polygon. This correctly
excludes empty areas inside a concave shape's bounding rectangle.

The screen's y coordinate grows downward. Therefore the lowest polygon vertex has
the largest local y coordinate. getBottom() finds that vertex and adds the body's y
position. If the bottom passes the ground line, fixGroundCollision() moves the
polygon upward by the overlap. The inherited PhysicsObject update then reverses and
reduces vertical velocity using the same bounce factor used by other shapes.


31. EXACT SCOPE OF THE WORD "SOLID"
-----------------------------------

The custom polygon is filled on screen and its geometry remains rigid while it
moves. It responds to gravity and the ground. However, this project does not detect
or resolve collisions between objects. A polygon may pass through another polygon,
circle, rectangle, or triangle. The built-in objects have the same limitation.

Object-to-object collisions are a separate extension. A common method for convex
polygons is the Separating Axis Theorem (SAT). Concave shapes would first need to
be divided into convex parts, or use a different collision approach. This feature
does not claim those interactions are already implemented.

33. REVIEW QUESTIONS ABOUT THE NEW FEATURE
------------------------------------------

Q1. How does the user draw a custom shape?

Answer: Press D, trace the outline while holding the left mouse button, then release.
Game collects the points and creates a CustomPolygon after validation.

Q2. Why is CustomPolygon derived from PhysicsObject?

Answer: It can use the same body, gravity, bounce, selection state, and object list.
It supplies its own implementations of drawing, point selection, and ground logic.

Q3. Why store vertices relative to an anchor?

Answer: The vertices describe fixed geometry and PhysicsBody stores the moving
position. Adding the body's position to a local vertex gives its current world
position, so the whole outline can move as one rigid object.

Q4. Why split a concave shape into triangles?

Answer: A convex polygon renderer may incorrectly fill a concave notch. Triangles
can represent the concave filled region accurately. Ear clipping finds those
triangles from the boundary.

Q5. How are mouse clicks tested against a concave outline?

Answer: Ray casting counts crossings of polygon edges. An odd number means the
point is inside; an even number means it is outside.

Q6. How does the custom polygon touch the ground?

Answer: It finds its lowest vertex, compares that world y coordinate with the
ground, shifts upward to remove overlap, then uses the base class bounce response.

Q7. Do custom shapes collide with other objects?

Answer: No. The current project handles gravity and ground contact only. Object
collision detection and response would be a separate feature.


34. SHORT UPDATED VIVA SPEECH
-----------------------------

Our project is a 2D Physics Sandbox made using C++, SFML, and CMake. We can spawn
circles, rectangles, and triangles, and now we can draw custom polygon shapes with
the mouse. Game collects and validates the outline, then creates a CustomPolygon
derived from PhysicsObject. This lets the new shape use the same polymorphic object
collection and update loop as the built-in shapes.

CustomPolygon stores its vertices relative to an anchor, which keeps its geometry
rigid while its body moves. It uses ear clipping to draw concave filled shapes,
ray casting to select a point inside the actual outline, and its lowest vertex to
respond to the ground. The physics remains intentionally introductory: objects
fall and bounce on the ground, but they do not collide with one another. The feature
demonstrates inheritance, polymorphism, encapsulation, geometry algorithms, and
event-driven input in one understandable example.
